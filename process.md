# Как мы разрабатываем DejaView

Этот документ описывает весь процесс работы: где заводить задачи, как их вести, как попадает код в проект.

## Две системы, каждая для своего

| Что | Где |
|---|---|
| Требования, задачи, подзадачи, учёт времени | **Redmine** — https://ai.nsu.ru/projects/dejaview |
| Код, ветки, Pull Request, ревью | **GitHub** — репозитории направлений |
| Контракты API, архитектура, соглашения | этот репозиторий (`dejaview-docs`) |

**Задачи ведём только в Redmine. GitHub — для кода.**

## Задачи в Redmine

- **Требования** (трекер Requirement) уже сформированы менеджером и аналитиками.
- Бакалавры создают **задачи** (трекер Task) под требованиями, берут их в работу и **обязательно логируют время** (трудозатраты) — это часть дисциплины КРПО.
- Крупная работа дробится на подзадачи (Task со ссылкой на родительскую / на Requirement).

Статусы задачи (Task):

```
New → In progress → Resolved → Closed
```

- **New** — задача заведена и назначена.
- **In progress** — исполнитель взял в работу.
- **Resolved** — сделано, ждёт приёмки менеджера.
- **Closed** — менеджер принял результат.
- **Need More Info** — нужны уточнения; **Feedback** — вернули на доработку.

## Жизненный цикл задачи (сквозной)

1. В Redmine есть **Task** (под Requirement), назначен исполнителю.
2. Исполнитель переводит в **In progress**, начинает работу, **трекает время**.
3. Код пишется в **GitHub**: ветка → коммиты → Pull Request → ревью куратора-магистранта.
4. PR влит в `main` → задача в Redmine переводится в **Resolved**.
5. Менеджер принимает → **Closed**. Если нужны правки — **Feedback**, вопросы — **Need More Info**.

## Учёт времени

Логируй потраченное время (Spent time) на свою задачу в Redmine. Без учёта времени задача не считается сделанной.

## Код в GitHub

- Ветка на задачу от `main`: `feat/<кратко>` или `fix/<кратко>` (см. [conventions.md](conventions.md)).
- В названии ветки удобно указывать номер Redmine-задачи: `feat/17123-audio-search`.
- В описании Pull Request — **ссылка на задачу Redmine**: `https://ai.nsu.ru/issues/17123`.
- Коммиты — по [Conventional Commits](conventions.md): `feat: ...`, `fix: ...`.
- Прямой push в `main` закрыт. Только через PR с одобрением магистранта (назначается по CODEOWNERS). Рекомендуем **Squash and merge**.

## Роли в процессе

| Роль | Кто | Что делает |
|---|---|---|
| Менеджер | Даниил | Требования, приоритеты, приёмка задач (Closed) |
| Куратор направления | магистрант | Ревью PR, помощь, архитектурные решения |
| Разработчик | бакалавр | Берёт задачи в Redmine, пишет код, открывает PR, трекает время |
| QA | бакалавр | Тестирование, заведение багов (трекер Bug) |

## Definition of Ready (задача готова к взятию)

- Понятно, что нужно сделать, есть критерии приёмки.
- Задача привязана к требованию, нет блокеров.

## Definition of Done (задача завершена)

- Код работает и проверен локально.
- PR прошёл ревью, замечания закрыты, влит в `main`.
- Время залогировано в Redmine.
- Документация обновлена, если менялось поведение или API.
- Задача переведена в Resolved/Closed.
