# Соглашения команды DejaView

## Git-flow

- `main` — защищённая ветка, всегда рабочая.
- На каждую задачу — своя ветка от `main`. Название: `<тип>/<кратко>`, например `feat/audio-search`, `fix/login-500`.
- Изменения вливаются в `main` только через Pull Request.

## Нейминг коммитов (Conventional Commits)

Формат: `<тип>: краткое описание` (описание можно по-русски).

Типы:

- `feat` — новая функциональность (фича)
- `fix` — исправление бага
- `refactor` — улучшение кода без изменения поведения
- `perf` — оптимизация производительности
- `docs` — документация
- `test` — тесты
- `chore` — рутина (зависимости, конфиги, CI)
- `style` — форматирование, без изменения логики

Примеры:

- `feat: поиск по аудиофрагменту`
- `fix: пустая выдача при коротком запросе`
- `refactor: вынести клиент TMDB в отдельный модуль`

## Привязка к задачам

Задачи ведём в **Redmine**: https://ai.nsu.ru/projects/dejaview

- В названии ветки указывай номер Redmine-задачи: `feat/17123-audio-search`.
- В описании Pull Request — ссылку на задачу: `https://ai.nsu.ru/issues/17123`.
- Не забывай логировать время (Spent time) в Redmine.

## Pull Request

- В описании: что сделано и как проверить (подставится шаблон).
- Минимум одно одобрение ревьюера — лид направления назначается автоматически по CODEOWNERS.
- Прямой push в `main` закрыт.

## Code style

- Python (backend, ml): PEP 8, форматтер black / ruff.
- JS/TS (frontend): ESLint + Prettier.

## Definition of Done

- Код работает и проверен локально.
- Пройдено ревью, замечания закрыты.
- Обновлена документация, если менялось поведение или API.
