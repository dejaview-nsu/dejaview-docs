# Соглашения команды DejaView

Техника работы с git. Процесс (кто заводит задачи, статусы, приёмка) описан в [process.md](process.md).

## Ветки

- `main` защищена и всегда рабочая, прямой push закрыт.
- На каждую задачу своя ветка от `main`: `<тип>/<номер задачи>-<кратко>`.
- Примеры: `feat/17155-audio-search`, `fix/17301-login-500`.

## Коммиты

Формат Conventional Commits: `<тип>: краткое описание`. Описание можно по-русски.

| Тип | Когда |
|---|---|
| `feat` | новая функциональность |
| `fix` | исправление бага |
| `refactor` | улучшение кода без изменения поведения |
| `perf` | оптимизация производительности |
| `docs` | документация |
| `test` | тесты |
| `chore` | зависимости, конфиги, CI |
| `style` | форматирование без изменения логики |

Примеры:

- `feat: поиск по аудиофрагменту`
- `fix: пустая выдача при коротком запросе`
- `refactor: вынести клиент TMDB в отдельный модуль`

## Pull Request

- В описании: что сделано и как проверить, плюс ссылка на задачу Redmine.
- Ревьюер назначается автоматически по CODEOWNERS, нужно одно одобрение.
- PR с падающими проверками влить нельзя.
- Рекомендуем Squash and merge.

## Code style

| Направление | Инструменты |
|---|---|
| Backend, C++ | clang-format |
| ML и офлайн-скрипты, Python | PEP 8, ruff или black |
| Frontend, TypeScript | ESLint, Prettier |

Проверки стиля выполняются в CI на каждый Pull Request.
